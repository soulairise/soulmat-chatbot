# 네이버 커머스 API 연결하기

스마트스토어 자료를 스크래핑 없이 **정식 인증 경로로** 가져오기 위한 설정입니다.
네이버가 봇 트래픽을 차단하기 때문에, 스토어 자료를 안정적으로 받으려면 이 방법뿐입니다.

---

## 1. 애플리케이션 발급 (사장님이 직접 하셔야 합니다)

1. **https://apicenter.commerce.naver.com** 접속 → 스마트스토어 판매자 계정으로 로그인
2. **애플리케이션 관리 → 애플리케이션 등록**
3. **권한 그룹에 "상품"을 반드시 포함**시킵니다
   - 이게 빠지면 나중에 `403 ROLE_NOT_FOUND` 가 납니다
4. 약관에 동의합니다
   - 빠지면 `403 PROVISION_NOT_FOUND` 가 납니다
5. 발급된 **애플리케이션 ID**와 **애플리케이션 시크릿**을 확보합니다
   - 시크릿은 `$2a$10$...` 으로 시작하는 긴 문자열입니다
   - **⚠️ 시크릿은 발급 화면에서만 보입니다. 지금 안전한 곳에 복사해 두세요**

## 2. 키 넣기

```bash
cd /Users/soulmat/소울매트업무/soulmat-chatbot/app
cp .env.example .env
```

`.env` 파일을 열어 두 줄만 채웁니다.

```
NAVER_CLIENT_ID=발급받은_애플리케이션_ID
NAVER_CLIENT_SECRET=$2a$10$발급받은_시크릿_전체
```

> **시크릿은 잘라내지 말고 `$2a$10$` 부터 끝까지 통째로** 넣으세요.
> 이 값이 bcrypt 전자서명의 솔트로 쓰이기 때문에, 한 글자만 빠져도 서명이 깨집니다.

> **⚠️ 시크릿을 채팅창이나 GitHub 에 붙여넣지 마세요.**
> `.env` 는 `.gitignore` 에 등록되어 있어 저장소에 올라가지 않습니다.
> 이 파일은 사장님 맥에만 있으면 되고, 저(Claude)도 값을 볼 필요가 없습니다.

## 3. 실행

```bash
npm run naver:fetch
```

수집되는 것:

| 파일 | 내용 |
|---|---|
| `src/data/sources/naver-bundle-groups.json` | 묶음배송 그룹 = **배송비 정책 원본** |
| `src/data/sources/naver-products.json` | 판매 중 상품 목록 |
| `src/data/sources/naver-channel-products.json` | 채널 상품 상세 = **배송비·반품비·교환비 금액** |

실행이 끝나면 배송비·무료배송 기준·반품배송비·교환배송비가 요약표로 출력됩니다.
그 값을 보고 자사몰과 다른 부분이 있으면 채널을 명시해 청크를 만듭니다.

## 4. 챗봇에 반영

```bash
npm run embed                  # 벡터 재생성
npm run eval -- naver-추가      # 고정 질문 12문항 회귀 확인

```

푸시하면 GitHub Actions 가 자동으로 다시 배포합니다.

## 오류가 나면

토큰 발급 실패 시 나오는 코드는 **공식 스펙에 정의된 값**입니다.

| 코드 | 원인 | 해결 |
|---|---|---|
| `400` + `client_secret_sign` | 전자서명 불일치 | 시크릿을 `$2a$10$` 부터 전체 복사했는지 확인 |
| `400` (그 외) | timestamp 만료 | 전자서명용 시각은 **5분간만 유효**합니다. 맥 시스템 시각이 맞는지 확인 |
| `403 ROLE_NOT_FOUND` | 권한 없음 | 애플리케이션에 **"상품" 권한 그룹** 추가 |
| `403 PROVISION_NOT_FOUND` | 약관 미동의 | API센터에서 약관 동의 |
| `403 INVALID_STORE_STATUS` | 스토어 상태 문제 | 스토어가 정상 영업 상태인지 확인 |
| `404 MEMBER_NOT_FOUND` | 판매자 ID 오류 | 본인 스토어만 볼 거면 `NAVER_ACCOUNT_ID` 를 **비워두세요** |

`npm run naver:fetch` 는 오류 코드에 맞는 해결 힌트를 함께 출력합니다.

## 구현 메모

- **인증 방식**: `bcrypt(clientId + "_" + timestamp, clientSecret)` → base64
  → `POST /v1/oauth2/token` (쿼리 파라미터)
  구현이 공식 문서의 예시 입출력과 **바이트 단위로 일치**함을 확인했습니다.
- **토큰 수명**: 3시간. 같은 프로세스 안에서는 캐시해 재발급하지 않습니다.
- **요청량 제한**: 상품 API 는 애플리케이션당 20 rps 입니다. 현재 상품 수에서는 여유가 충분합니다.
- **보안 경계**: `scripts/naverCommerce.mjs` 는 **Node 전용**입니다.
  브라우저 앱에서 import 하면 시크릿이 노출되므로 절대 하지 마세요.
  API 응답은 빌드 단계에서 JSON 으로 떨어지고, 앱에는 **결과 벡터만** 넘어갑니다.
- **자동 청크화는 일부러 하지 않았습니다.** API 응답을 검증 없이 청크로 만들면
  잘못된 값이 그대로 챗봇 답변의 근거가 됩니다. 사람이 요약표를 보고 확인한 뒤 옮깁니다.
