# 소울매트 구매 안내 챗봇

soulmat.kr 공개 자료에만 근거해 답하고, **그 근거와 자동 판정을 함께 보여주는** RAG 챗봇입니다.
서버가 답을 만들지 않습니다. 페이지를 연 사람의 컴퓨터에서 Ollama가 답변 생성과 질문 임베딩을 모두 처리합니다.

- 배포 주소: **https://soulairise.github.io/soulmat-chatbot/**
- 기획 문서: [PRD.md](./PRD.md)
- 실험 기록: [results/](./results/)

---

## 사용 조건 — 열기 전에 확인하세요

이 페이지는 정적 웹페이지이고, 답변은 **당신 컴퓨터의 Ollama**가 만듭니다. 아래 3가지가 갖춰져야 동작합니다.

**1. Ollama 설치 및 실행** — [ollama.com/download](https://ollama.com/download)

**2. 모델 준비** (합계 약 2.5GB)

```bash
ollama pull qwen3.5:2b
ollama pull embeddinggemma:300m
```

**3. 이 페이지 주소에서의 호출 허용 (CORS)**

```bash
# macOS
launchctl setenv OLLAMA_ORIGINS "https://soulairise.github.io"
# Linux
export OLLAMA_ORIGINS="https://soulairise.github.io"
# 설정 후 Ollama 재시작
```

Ollama가 꺼져 있으면 오류 화면 대신 위 3단계 안내가 표시됩니다.
**첫 방문에 임베딩 모델을 브라우저로 내려받는 절차는 없습니다.** 그 이유는 아래 설계 결정에 적었습니다.

---

## 설계 결정 요약

### 1. 임베딩을 브라우저가 아니라 Ollama에서 돌린다

교안의 참조 구현은 `onnx-community/embeddinggemma-300m-ONNX`를 브라우저 WASM에서 실행합니다.
이 프로젝트는 **같은 모델을 Ollama의 `embeddinggemma:300m`으로** 실행합니다.
모델도 차원(768)도 동일하므로 교안이 요구하는 벡터 공간을 그대로 지킵니다.

| | 교안 기본 경로 | 이 프로젝트 |
|---|---|---|
| 모델 | embeddinggemma-300m | embeddinggemma:300m (동일) |
| 차원 | 768 | 768 (동일) |
| 실행 위치 | 브라우저 WASM (`no_gather_q4` 양자화) | Ollama |
| 첫 방문 다운로드 | 약 200MB | **없음** |
| 추가 의존성 | transformers.js | 없음 (Ollama는 생성 때문에 어차피 필요) |

답변 생성 때문에 Ollama는 어차피 있어야 하므로, 임베딩까지 옮겨도 사용자 부담은 늘지 않고
첫 방문 다운로드 200MB가 사라집니다. 양자화 손실도 없습니다.

**주의한 함정**: EmbeddingGemma는 문서와 질의에 서로 다른 프리픽스를 요구합니다.
빌드(Node)와 런타임(브라우저)이 프리픽스를 다르게 붙이면 같은 모델이라도 벡터 공간이 어긋납니다.
그래서 프리픽스 규약을 [`src/lib/embedPrompt.mjs`](./app/src/lib/embedPrompt.mjs) 한 파일에 두고
양쪽이 **같은 파일을 import** 하게 했습니다.

```js
docPrompt   = `title: ${section} | text: ${text}`
queryPrompt = `task: search result | query: ${q}`
```

### 2. 판정(Judge)에서 LLM에게는 원자적 사실만 묻는다

처음에는 판정 6필드 전부를 `qwen3.5:2b`에 한 번에 맡겼습니다. 실패했습니다.

- 정당한 거절을 `verdict: fail`로 판정 — "정당한 거절도 pass"라는 분기 규칙을 2B 모델이 못 지킴
- `[1][2]`가 명백히 있는 답변을 `cited: false`로 판정

그래서 **역할을 나눴습니다.**

| 판정 항목 | 누가 정하는가 |
|---|---|
| `cited` | **정규식** `/\[\s*\d+\s*\]/` — 문자열 존재는 결정적으로 확인 가능하다 |
| `hallucinated` / `refusal` / `answerable` / `covered` | LLM — 서로 독립적인 단일 판단만 묻는다 |
| `grounded` / `relevance` / `verdict` | **코드** — 위 원자 판단을 규칙으로 조합한다 |

모델에게 "종합 평가"를 시키지 않고 조합 책임을 코드로 옮기자 판정이 안정됐습니다.

### 3. 자료의 모순은 청크에 넣지 않는다

자사몰 수집 중 당일발송 마감시간, 상담시간, 배송 소요일이 페이지마다 다르게 적혀 있었습니다.
RAG는 이런 모순을 그대로 근거로 삼아 확신 있게 틀립니다.
그래서 **법정 고지 페이지(`/shopinfo/guide.html`) 값만 정본으로 채택**하고,
상품 상세의 상충하는 문구는 청크에서 제외했습니다. 상세 내역은 PRD 6절에 있습니다.

### EXP-01 — 자동 판정을 그대로 믿으면 안 된다

judge는 12/12 pass를 냈지만, 답변을 직접 읽으니 최소 3건이 틀렸습니다.

- `요가매트 세탁해도 되나요?` → "세탁 가능 여부에 대한 안내는 없습니다"
  **SM-016에 "물세탁이 가능해 위생적입니다"가 있고 유사도 0.693으로 1위 검색된 상태였습니다.**
  답할 수 있는데 거절한 것인데 judge는 `pass`를 줬습니다.
- `5만원어치 사면...` → "비용은 구매 후 1~5일 이내에 수령됩니다" (문장이 성립하지 않음)
- `요가 초보인데...` → 거절하지 않고 뜻이 통하지 않는 문장을 생성

**교훈**: LLM-as-a-Judge의 pass 개수는 품질 지표가 아니라 관찰의 출발점이다.
교안이 "생성 문장이 자연스럽다는 사실과 출처를 가진 답이라는 사실은 다르다"고 한 것이 판정기에도 똑같이 적용된다.

### EXP-02 — 프롬프트 누출, 그리고 내가 틀렸던 지점

EXP-01의 과잉 거절을 프롬프트 탓으로 보고 규칙을 추가했습니다.

```
3. 자료에 답이 있으면 반드시 답합니다. 자료가 질문에 답하고 있는데도
   "확인되지 않는다"고 말하는 것은 규칙 위반입니다.
```

pass가 8/12로 떨어졌고, 재고 질문 답변에 **시스템 프롬프트가 그대로 노출**됐습니다.

> 소울매트 공개 자료에는 ... 재고 수량 정보가 포함되어 있지 않습니다. **자료가 질문에 직접 답하고 있는데도 "확인되지 않는다"고 말하는 것은 규칙 위반입니...**

"규칙 위반입니다" 같은 **메타 문장은 모델에게 인용 가능한 본문으로 보입니다.**
지시는 모델이 따를 행동으로 쓰고, 모델을 평가하는 말투로 쓰지 않아야 합니다.

**그리고 여기서 제가 내렸던 결론이 틀렸습니다.** EXP-01/02는 둘 다 temperature 0.2였습니다.
온도만 0으로 고정하고 EXP-01의 프롬프트를 다시 돌리자(EXP-01') **11/12로 EXP-03과 같은 결과**가 나왔습니다.
즉 EXP-01의 과잉 거절은 프롬프트가 아니라 **샘플링 변동**이었습니다.
변수 하나만 바꾼다는 원칙을 지켰다고 생각했지만, 실제로는 **통제되지 않은 노이즈가 변수를 덮고 있었습니다.**
근거 기반 QA에서 창의성은 필요 없으므로 이후 실험은 전부 `temperature: 0`으로 고정했습니다.

메타 규칙 제거(EXP-03)는 측정으로 우열이 증명되지는 않았지만,
**누출이 실제로 관측된 문장**이므로 되돌리지 않고 유지했습니다.

### EXP-04 — 성능을 바꾼 것은 프롬프트가 아니라 청크 설계였다

EXP-01'과 EXP-03 양쪽에서 안정적으로 남은 결함은 색상 질문 하나였습니다.

> 트래블 요가매트의 색상은 드림캐쳐그린, 밀키웨이, 만다라 등 **15종의 민무늬**와 컬러플트라이앵클 스웨이드 요가매트 등 다른 제품과 구별됩니다

15종 중 민무늬는 4종뿐인데 전부 민무늬로 뭉갰고, 무관한 3mm 제품까지 끌어왔습니다.
원인은 프롬프트가 아니라 **한 청크에 15개 색상과 민무늬 표기를 몰아넣은 자료 설계**였습니다.

```
SM-011  : 색상 15종 중 패턴 11종 — 드림캐쳐그린, 밀키웨이, ...
SM-011B : 색상 15종 중 민무늬 4종 — 블루레이크, 옴 그레이, 물란다라 핑크, 아즈나 네이비
```

프롬프트를 건드리지 않고 청크만 둘로 나누자 `pass`로 바뀌었고, 답변이 민무늬 4종을 정확히 구분했습니다.
**모델을 바꾸기 전에 자료를 먼저 본다** — 이 프로젝트에서 가장 비용 대비 효과가 큰 개입이었습니다.

### EXP-05 — 채널이 다르면 답도 달라야 한다

네이버 커머스 API로 스마트스토어 자료를 받아보니 **같은 브랜드인데 채널마다 정책이 달랐다.**

| | 자사몰 soulmat.kr | 네이버 스마트스토어 |
|---|---|---|
| 배송비 | 5만원 미만 3,000원 | 39개 중 27개 무료, 나머지 2,900/3,500원 |
| 반품비 | "고객 부담" (금액 없음) | 상품별 2,990 ~ 3,900원 |
| 취급 상품 | 매트·요가용품 | + 의류, 명상소품, 담요, 렌탈, 단체 OEM |

한 청크에 섞으면 자사몰 방문자에게 스마트스토어 가격을 답하게 된다.
그래서 값이 갈리는 기존 청크에 `자사몰(soulmat.kr) 기준으로` 를 명시하고,
스마트스토어 청크 14개를 별도 ID 대역(`NS-*`)으로 추가했다.
프롬프트에도 "비용을 답할 때 채널을 밝히고, 질문에 채널이 없으면 둘 다 안내" 규칙을 넣었다.

### EXP-06 — 판정 점수를 올렸다면 버그를 못 고쳤다

EXP-05에서 이런 답이 나왔다.

> **요가바지도 파나요?** → "소울매트 공개 자료에는 요가바지 판매 정보가 **없습니다**"

`NS-010` 에 여성 요가 하렘팬츠 19,800원이 있고 **그 청크가 1위로 검색된 상태**였다.
원인은 임계값이었다. 유사도 0.502가 기준 0.55에 걸려 '약한 근거' 경고가 뜨고,
그 경고가 프롬프트에 실려 모델을 거절 쪽으로 밀었다.

고정 질문 세트의 실측 분포를 보면 두 집단이 겹치지 않는다.

```
자료 밖 질문 최고점   0.438   (재고 질문)
도메인 내 질문 최저점  0.502   (요가바지)
교안 기준값          0.55    ← 도메인 내 질문까지 잘라냄
```

`embeddinggemma` 의 한국어 코사인 분포가 교안의 모두콘 자료보다 낮게 나온다.
**임계값은 자료마다 다시 재야 하는 값이지, 그대로 가져다 쓰는 상수가 아니다.**
0.47로 조정하자 답이 바뀌었다.

> "자사몰에는 요가바지가 포함되어 있지 않습니다. 하지만 **스마트스토어에서는 여성 요가 하렘팬츠 등** 다양한 요가 의류를…"

**그런데 판정기는 이 정답에 `warn` 을, 앞의 오답에 `pass` 를 줬다.**
전체 pass 는 14/16 → 12/16 으로 떨어졌지만 답변은 정확해졌다.
판정 점수를 목표로 삼았다면 이 버그를 고치는 변경을 되돌렸을 것이다.
EXP-01 의 교훈이 반복된다 — **pass 개수는 품질이 아니라 관찰의 출발점이다.**

### EXP-07 — 내가 만든 평가 질문은 내 자료에 맞춰져 있었다

네이버 커머스 API 로 스마트스토어에 실제로 들어온 상품문의 7건을 받아
그대로 검색에 넣어봤다. **근거를 찾은 질문이 0건이었다.**

| 실제 고객 질문 | 최고 유사도 | 원인 |
|---|---|---|
| 매트 사이즈가 어떻게 되나요? | 0.440 | 치수가 청크에 없음 |
| 모래·잔디에서 쿠션감 있나요? | 0.293 | 사용 환경 정보 없음 |
| 옴그레이랑 그레이랑 같나요? | 0.344 | 색상명 대응 없음 |
| 물 온도 몇 도? 세탁망 필요? | 0.322 | "세탁 가능"까지만 있음 |

EXP-01~06 의 고정 질문 16개는 **내가 가진 자료를 보고 만든 질문**이었다.
그래서 잘 나왔다. 실제 고객은 치수, 사용 환경, 색상 대응, 세탁 상세를 묻는다.
**평가 질문을 스스로 만들면 평가가 자기 자료의 거울이 된다.**

다행히 답은 이미 있었다. 판매자가 그 7건에 직접 쓴 답변이
가장 정확한 청크 재료였다. 거기서 사실 15개를 뽑아 `CS-*` 대역으로 추가했다
(183×61cm, 25도 이하 세탁, 세탁망 불필요, 건조기 변형 위험, 옴그레이=그레이 등).
고정 질문 세트도 16 → 23문항으로 늘리고 **실제 문의 7건을 영구 포함**시켰다.

결과는 실제 질문 7건 전부 pass. 남은 2건(재입고·카톡 리뷰)은
설계상 범위 밖이며, 자료가 없다고 밝히고 톡톡으로 안내하는 것이 정답이다.

### 아직 해결하지 못한 것

- `요가 초보인데 어떤 자세부터 하면 되나요?` — 거절해야 하는데 뜻이 통하지 않는 문장을 만들고, judge는 `pass`를 줍니다. 자료 밖 판단이 "명백한 무관"이 아니라 "약하게 관련"일 때(코사인 0.409) 2B 모델이 흔들립니다.
- 당일발송 마감시간·상담시간은 자사몰 자료 자체가 모순이라 **답하지 못합니다.** 자사몰 수정이 선행되어야 합니다.

## 스마트스토어 자료 (네이버 커머스 API)

스마트스토어는 봇 트래픽을 차단하므로 스크래핑이 아니라 **커머스 API** 로 가져옵니다.
설정 방법은 [docs/네이버커머스API-연결.md](./docs/네이버커머스API-연결.md) 에 있습니다.

```bash
cd app && cp .env.example .env   # 키를 채운 뒤
npm run naver:fetch              # 배송비·반품비 원본 수집
```

인증은 `bcrypt(clientId + "_" + timestamp, clientSecret)` → base64 전자서명 방식이고,
구현이 공식 문서의 예시 입출력과 일치함을 확인했습니다.
`scripts/naverCommerce.mjs` 는 **Node 전용**이며 브라우저 앱에서 import 하지 않습니다 —
API 응답은 빌드 단계에서만 쓰이고 앱에는 결과 벡터만 넘어갑니다.

## 실행 방법

```bash
cd app
npm install
node scripts/embed.mjs   # 청크 → 벡터스토어 생성 (Ollama 필요)
```

```bash
npx tsx scripts/eval.mts <실험이름>   # results/<실험이름>.md 생성
```

배포:

```bash
npm run build            # dist/ 생성 (base:'./' 로 상대 경로)
```

## 한국어 BM25에 대하여

한국어는 조사가 붙어 어절 단위 완전일치가 잘 되지 않습니다(`배송비는` vs `배송비`).
그래서 어절 토큰과 **한글 2-gram을 함께** 색인합니다 ([`rag.ts`](./app/src/lib/rag.ts)).
하이브리드 순위는 코사인 0.7 + BM25 0.3이고, **약한 근거 판정은 정규화 이전의 원본 코사인 값**으로 합니다.
정규화된 값은 1위가 항상 1이 되어 0.55 임계값이 의미를 잃기 때문입니다.
